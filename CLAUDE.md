# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

**ECHO ARCHIVE** — a fashion-brand static site (홈·브랜드 소개·제품·포트폴리오·문의) deployed on Cloudflare Workers, with a lightweight admin CMS for the brand's own product/portfolio content. Public runtime is plain HTML/CSS/vanilla JS by policy — **no framework, bundler, or `npm` build step** (there is no `package.json`). The authoritative rules for what can/can't be touched, commit/branch naming, and the deploy procedure live in `AGENTS.md` — read it before making structural changes; this file only covers things AGENTS.md doesn't (technical architecture, commands, non-obvious behavior).

## Commands

```bash
node --test tests/*.test.mjs                                   # run all tests
node --test tests/home-contract.test.mjs                       # single file
node --test --test-name-pattern="이름" tests/home-contract.test.mjs   # single test by name
node --check some-file.js                                      # syntax-check one JS file
```

There is no dev server script. To preview `products.html`, `product.html`, or `portfolio.html` locally, serve the repo root over plain HTTP (e.g. `npx serve .` or any static file server) rather than opening the file directly — these pages `fetch("products.json")`/`fetch("portfolio.json")`, and Chromium blocks `fetch` between `file://` origins with a CORS error. `index.html`, `about.html`, and `contact.html` have no fetch calls and can be opened directly.

CI runs `.github/scripts/validate_site.py --base <sha> --head <sha>` (needs `python3`, not installed in every environment) as the `validate-site` required check on PRs into `main`. It rejects: any diff touching a protected file (see AGENTS.md) or anything under `.github/`; a changed file over 12MB; invalid JSON anywhere in the tree; `node --check` failure on any `.js`; a missing core page (`index.html`, `about.html`, `contact.html`, `products.html`, `product.html`, `portfolio.html`); duplicate `id` attributes or a broken local `href`/`src`/`poster`/`srcset`/CSS `url()` reference in any HTML/CSS file; leftover `<<<<<<<`/`=======`/`>>>>>>>` conflict markers. `main` has branch protection (PR + merge queue) — direct `git push` to `main` is rejected by GitHub itself.

## Architecture

### Two Cloudflare Workers share one `worker.js`

`wrangler.jsonc` deploys the **public** site (`ADMIN_ENABLED=false`; `run_worker_first` only intercepts `/api/admin/*`, `/images/products/*`, `/images/portfolio/*`, `/portfolio.json` — everything else is served as a static asset). `wrangler.admin.jsonc` deploys a **separate standalone admin** worker (`ADMIN_ENABLED=true`, `run_worker_first: ["/*"]`, allowlists only `/admin*` and vendor editor assets). Both configs point at the same `worker.js`; it branches on the `ADMIN_ENABLED`/`ADMIN_STANDALONE` env vars.

### The Git repo, not a database, is the source of truth for content

Admin saves (`/api/admin/catalog`, `/api/admin/portfolio`, `/api/admin/image`) go through `worker.js` calling the **GitHub Contents API** directly — each save is a real commit to `main` (optimistic concurrency via `expectedSha`; writes fan out to every repo listed in the `GITHUB_REPOS` env var, e.g. `eco-archive-gpu,eco-archive-aura`). There is no KV/D1/R2 involved. `main` carries a GitHub ruleset requiring PRs for ordinary pushes, but the admin worker's automated commits bypass it — that path is not blocked. The write order within a save is **replicas first, primary (`eco-archive-gpu`, the repo this public site deploys from) last**; a mid-loop failure on any replica throws before the primary write ever runs, so a partial failure can leave repos diverged (see `writeGitHubFile` calls in the `/api/admin/catalog` and `/api/admin/portfolio` PUT handlers). Reads are asymmetric and this trips people up:
- `portfolio.json` and `images/products/*`/`images/portfolio/*` are **live-proxied** by the public worker straight from GitHub's raw content, so admin edits to those appear immediately, before any redeploy.
- `products.json`'s own text fields (name/price/description/etc.) are served as a **plain static asset** and stay stale until the next deploy. This is existing, intentional platform behavior — don't "fix" it by hand-editing `worker.js` (protected) or by hardcoding product data into HTML. A commit to `main` triggers Cloudflare's own GitHub-App-based auto-deploy ("Workers Builds" check on the commit); in practice this completes in roughly 1-2 minutes, which is exactly what the admin save toast tells the person saving — a report of "my edit isn't showing up" immediately after saving is very likely just that window, not a bug. Confirm by checking whether the GitHub commit landed (`git fetch`, `git log origin/main`) and whether its "Workers Builds" check run succeeded before assuming the pipeline is broken.

### Admin content only ever reaches the DOM through `catalog.js`

`window.ProductCatalog` (`catalog.js`, protected — don't edit its security functions) is the single chokepoint: `loadVisibleProducts()`, `safeImageUrl`, `safeExternalUrl`, `safeVideoEmbedUrl`/`safeVideoFileUrl`, and `sanitizeRichText` are what every public page calls to turn `products.json`/`portfolio.json` into markup. `sanitizeRichText`'s tag/attribute allowlist and `rich-content.css`'s selectors (`[data-align]`, `[data-brand-font]`, `big[data-brand-size]`, `section[data-brand-gallery]`, task-list `li[data-task]`, etc.) are two halves of the same contract — the CSS only styles what the sanitizer lets through, so changing one without the other silently breaks rendering. `products.html`/`product.html`/`portfolio.html` build their DOM in **inline `<script>` blocks** in the HTML file itself (not separate `.js` files), so that's where to look when changing how a listing or detail page renders.

### `product.html`'s carousel and purchase dialog are a DOM-attribute contract

The inline script wires up `[data-product-carousel]` / `[data-carousel-slide|previous|next|index|current]` and `#purchaseDialog` / `[data-purchase-dialog]` / `.purchase-dialog-close` purely by class/attribute selectors. A redesign can restyle freely but must keep these names — the JS does no null-checking on some of them and will throw if a name drifts.

### The home page is a separate visual subsystem from the other 5 pages

`index.html`'s TV-wall hero is positioned with **percentages measured against the exact 1586×992 canvas of the original design reference**, not eyeballed — that part hasn't changed. But the TVs themselves (cabinet, screen glass, knobs/LED, and the antenna/ear/wing/tail decorations) are drawn entirely with CSS gradients and inline SVG, not photos — there is no `.tv-shell` image and no `images/tv/*`/`images/decor/*` raster art for the TVs (only `images/decor/stage-floor.webp`, the reflection under the TVs, is still a photo). This was a deliberate move away from AI-rendered PNG/WebP composites: baked-in screen graphics couldn't react to click/hover/`aria-pressed`, and independently-rendered decor layers had visible alpha-fringing against the light background. Moving or resizing a TV/decoration still means re-measuring its bounding box against the 1586×992 canvas — see the `.tv[data-tv-index]` / `.tv-decor-*` rules in `style.css` — but the content inside each box is now hand-authored `<svg>` (per-TV screen icon) or CSS gradients (`.tv`, `.tv-screen`, `.tv-led`, `.tv-knob`), so changing an icon means editing the inline SVG path in `index.html`, not swapping an asset file. Behavior (BGM toggle, one-time channel-tuning intro, page-to-page "signal" transition) lives in `scripts/home.js` (DOM/event wiring) + `scripts/home-logic.js` (pure, unit-tested state machine — BGM reducer, YIN/YANG polarity query resolution) + `scripts/motion.js` + `scripts/components/signal-transition.js`. The BGM TV has no approved audio file yet (`BGM_SRC = null` in `home.js`); clicking it doesn't touch the reducer at all — it adds `.is-bgm-unavailable`/a shake animation instead of flipping `aria-pressed`, precisely so it doesn't look like a broken toggle. `scripts/components/echo-tv-wall.js` is an unreferenced leftover from an earlier iteration of the home page — nothing loads it. `scripts/capsule-data.js` (the YIN/YANG→product-name presentation map, `window.EchoCapsuleData`) *is* wired up, but only into `products.html` (not `index.html`) — the home TV's `?polarity=YIN|YANG` links are read there via `EchoHomeLogic.resolvePolarityQuery`/`resolveProductPolarity`. Because the capsule map's product names (`CAT_404`, `DOG_404`, …) don't match whatever is actually in the live `products.json`, the filter currently always falls back to showing everything — by design (`filterProductsByPolarity` degrades to the unfiltered list rather than showing nothing), with a `#polarityBanner` telling the visitor that's what happened.

### The five non-home pages share a "SIGNAL SHEET" system

`about.html`/`products.html`/`product.html`/`portfolio.html`/`contact.html` open with the same anatomy so navigating between them reads as "the same channel system": a `.channel-head`/`.page-head` block (`.channel-code` reading `CH.0X SIG_XXXX` + `.channel-stamp` with the season line), `.yy-rule` section dividers (a half-black/half-white bar whose `.yy-rule-node` slides on scroll via an `IntersectionObserver` in `script.js`), and `.nav-menu a[data-ch="01|02|04|05"]` (product.html is `CH.03`, reachable only from a product card, not the nav) with a TV-style LED lit on the active channel. `.card`/`.archive-card` uses a CSS counter (`counter-reset: archive-ep` on `.grid`, `.card-ep::before { content: "EP." counter(...) }`) to number listings automatically — no per-item markup needed. **Gotcha**: `[hidden]` on anything that also matches a rule setting `display` (`.card { display: grid }`, `.filter-rail { display: flex }`) needs its own `.card[hidden] { display: none }` override, because equal-specificity + later-in-file authored CSS beats the UA `[hidden]` default — this already bit the `products.html` category filter once (cards didn't actually hide when "filtered out"). `tests/subpage-contract.test.mjs` locks the channel-head/nav-code/EP-badge/`product.html` DOM-contract pieces of this down.

### Design tokens: two eras coexist in `style.css`'s `:root`

The original dark theme (`--studio`, `--charcoal`, `--cream`, `--signal`, `--line-dark/light`) has no remaining consumers anywhere in the stylesheet — it's dead but left defined. The live look across **all six pages** (home + about/products/product/portfolio/contact) is the ice/chrome system: `--ice-0/1/2`, `--chrome-*`, `--stage-ink*`, `--glow-cool*`, plus the reusable `.glass-panel`/`.glass-corners` component (a layered-gradient "acrylic panel" look, same technique as the home page's TV screen glass) that the five non-home pages share via their `.card`/`.about-hero-panel`/`.value-card`/`.contact-item`/`.product-hero-gallery`/`.portfolio-content` etc.

### Tests

`tests/*.test.mjs` uses Node's built-in `node:test`/`node:assert` only — no test framework, no jsdom (everything is regex/string assertions over the raw HTML/CSS/JS text, not a rendered DOM). `home-contract.test.mjs` asserts `index.html`'s static markup (exactly 5 `data-tv-role` elements, correct link/button roles, no visible text baked into the TV screens, decorations excluded from the a11y tree) plus the pure logic exported by `scripts/home-logic.js`. `home-assets.test.mjs` asserts the CSS/SVG-only rendering contract (no `.tv-shell`/`<img>` inside any TV, every screen has an inline SVG icon, decor wrappers hold `<svg>` not `<img>`, `.tv-led`/`.tv-knob` exist as real CSS-drawn elements, and decor SVGs use the webtoon 선화+셀 셰이딩 convention — stroke outline + ≥2 fill tones). `subpage-contract.test.mjs` covers the SIGNAL SHEET system described above across the five non-home pages, plus the `product.html` DOM-attribute contract and the YIN/YANG polarity wiring.
